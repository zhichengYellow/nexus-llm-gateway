# Nexus 实际节省效果实测(1M token)

> 测试时间: 2026-08-07
> 脚本: `benchmark/live-saving-test.mjs`(可复现)

## 结果

| 指标 | 数值 |
|---|---|
| 请求数 | 190(长文档×150 / 重复调试×10 / 相似提问×20 / 长对话×6 / 简单问答×36 / 复杂任务×2) |
| 流量规模(不优化应产生) | **1,239,524 token(≈1.24M)** |
| 缓存命中率 | 95.8% |
| 不优化成本(直接调用上游) | $0.0170 |
| 走网关实际成本 | **$0.0085** |
| **节省成本** | **$0.0085(50%)** |
| **TRR(Token 节省率)** | **50.0%** |
| **CSR(成本节省率)** | **50.0%** |

## 复现方式

```bash
# 网关运行 + 已配 deepseek key
GATEWAY_MASTER_KEY=<master_key> MODEL=deepseek-v4-flash ROUNDS=150 \
  node benchmark/live-saving-test.mjs
```

- `MODEL` 默认 `auto`(受上游配额影响,可显式指定 deepseek-v4-flash)
- `ROUNDS` 控制长文档重复次数,150 ≈ 1.2M token

## 节省构成(诚实口径)

- **节省主要来自语义缓存**:长文档重复 150 次(第 1 次真实调用,后 149 次缓存直返)+ 相似提问语义命中 → 95.8% 请求零上游成本
- **50% 口径含义**:约一半流量(缓存命中)完全不产生成本,一半真实调用 → TRR/CSR = 50%
- 实际花费 $0.0085 仅为非缓存请求(简单问答、相似未命中、长文档首次)的 deepseek 真实成本

## 场景适用性

| 使用模式 | 预期节省 | 说明 |
|---|---|---|
| 调试/Agent/工具调用(重复度高) | **40-70%** | 缓存命中为主,本项目实测场景 |
| RAG/长文档反复分析 | 50%+ | 同文档重复查询命中 |
| 全新内容聊天(无重复) | 10-30% | 仅压缩/路由收益,缓存贡献小 |
| 全 auto + 多 Provider | 取决于配额 | **发现: provider 配额耗尽(如 gemini 429)时 auto 不 fallback,会失败**——待修 |

## 过程中发现并修复的问题

1. `recordUsage` 不写 `savedTokens`(节省数据全丢)→ 已修
2. 缓存命中虚拟成本被计入"实际成本",CSR 虚低 → 已修(缓存命中 costMicro=0,成本全部记为节省)
3. **待修: auto 路由在 provider 429/不可用时无 fallback**(DB 未配 fallbacks 时单点失败)——生产建议优先修
