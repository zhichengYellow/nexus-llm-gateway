# ADR 005: 缓存 Canonical Key 设计

- **状态**: ✅ 已采纳
- **日期**: 2025-02
- **决策者**: Nexus Team

## 背景

语义缓存需要判断两个 Prompt 是否"相同"，从而决定是否返回缓存结果。需要在命中率和准确性之间取得平衡。

## 决策

采用 **Canonical Key** 策略：对 Prompt 进行标准化处理，标准化后相同的 Prompt 视为同一请求。

## 设计细节

### 标准化规则

1. **Trim + 空白折叠**：`"  你好  "` → `"你好"`
2. **首尾语气标点剔除**：`"hello！"` → `"hello"`
3. **小写化**：`"HELLO"` → `"hello"`
4. **中间代码符号保留**：`"C++"` 不会变成 `"c"`，防止 False Positive

### 缓存 Key 组成

```
SHA-256({provider}|{model}|{canonical_text}|t{temperature_bucket})
```

- Provider + Model 隔离：不同模型的缓存互不污染
- Temperature 分桶：`<0.3 → 0`, `0.3~0.8 → 0.5`, `≥0.8 → 1`

## 理由

1. **优先避免 False Positive**：错误命中比不命中危险得多（C++ 变 c、1+1 变 11 是灾难性的）
2. **简单可靠**：精确匹配比向量相似度搜索更可控
3. **参数分桶**：微小参数差异不应破坏缓存命中

## 替代方案

### 纯向量相似度
- ✅ 可处理同义改写
- ❌ False Positive 风险高
- ❌ 需要 embedding 调用增加延迟

### 不做标准化
- ✅ 实现简单
- ❌ `"hello！"` 和 `"hello"` 不会命中同一缓存，命中率低

## 影响

- 缓存命中依赖 Prompt 的精确标准化
- 保留了 `embedding` 向量字段，为未来语义相似度搜索预留空间
